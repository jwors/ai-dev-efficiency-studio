## 一、现状分析

### 1.1 当前实现概览

产物系统是 AI Efficiency Studio 中用于管理和存储 AI 生成文件的核心模块。

**数据模型**
```prisma
model Artifact {
  id        String   @id @default(cuid())
  path      String   // 文件存储路径
  url       String   // 访问 URL
  filename  String   // 文件名
  kind      String   // 产物类型
  size      Int      // 文件大小（字节）
  createdAt DateTime @default(now())

  @@index([createdAt])
}
```

**存储策略**
- 数据库优先：元数据存储于 PostgreSQL
- 降级机制：数据库不可用时降级为 `public/artifacts/index.json` 文件存储
- 容量限制：最多保留 200 条记录

**支持的任务类型**
| 任务类型 | 功能 | 输出 |
|---------|------|------|
| `artifact.export` | 导出文件作为产物 | 下载链接 |
| `export_flow` | 导出流程图 | PNG/图片文件 |

**前端展示**
- 首页底部显示当前会话的下载链接
- 简单的 `<a>` 标签实现下载

### 1.2 存在的问题

#### 问题 1：缺少用户隔离（高危）
```
当前状态：Artifact 表无 userId 字段
风险影响：
  - 用户 A 的产物，用户 B 可见、可下载
  - 严重隐私泄露风险
  - 多租户场景无法部署
```

#### 问题 2：产物管理能力缺失
```
当前状态：仅支持下载
缺失功能：
  - 产物列表查看
  - 产物删除
  - 批量操作
  - 产物预览
```

#### 问题 3：存储资源无限增长
```
当前状态：无过期、无清理、无配额
风险影响：
  - 磁盘空间持续增长
  - 无用文件无法回收
  - 运维成本增加
```

#### 问题 4：产物与来源脱节
```
当前状态：产物无来源信息
影响：
  - 无法追溯生成会话
  - 无法复现生成过程
  - 用户体验割裂
```

#### 问题 5：产物类型利用不足
```
当前状态：kind 字段存在但未使用
影响：
  - 无法分类筛选
  - 无法差异化处理
  - 无法统计分析
```

### 3.4 存储治理机制

**配额控制**
```typescript
interface UserQuota {
  artifactCount: number;    // 最大产物数量（如 100）
  artifactSize: number;     // 最大存储空间（如 100MB）
  artifactTTL: number;      // 默认保留天数（如 30天）
}
```

**自动清理策略**
```
清理规则：
1. 超过配额的产物，按访问时间 LRU 淘汰
2. 超过 TTL 且未访问的产物，标记待清理
3. 用户手动删除的产物，立即清理文件
4. 定时任务：每日凌晨执行清理
```

**智能分类实现**
```typescript
function classifyArtifact(filename: string, content?: string): ArtifactKind {
  const ext = path.extname(filename).toLowerCase();

  const mimeTypeMap: Record<string, ArtifactKind> = {
    '.md': 'document.markdown',
    '.pdf': 'document.pdf',
    '.ts': 'code.typescript',
    '.py': 'code.python',
    '.json': 'data.json',
    '.csv': 'data.csv',
    '.png': 'media.image',
    '.jpg': 'media.image',
  };

  return mimeTypeMap[ext] || 'document.txt';
}
```
